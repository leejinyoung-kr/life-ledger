# 0005. 공통 기능은 별도 레포의 패키지(young-core)로 빼고, 그 레포는 비공개로 둔다

- **상태**: 채택 (소급 기록)
- **결정일**: 2026-07-17 (근거 커밋 `c2fdb9b`) · young-core 로 교체 2026-10-05 (`c6cb96f`) · 비공개 유지 2026-10-15 (`b265913`)
- **기록일**: 2026-10-18
- **결정 방식**: AI 제안을 그대로 채택 — 당시 대안 검토는 없었다. 비공개 유지만 본인이 정했다

## 맥락

- 인증 · 암호화 · 파일 저장 · 메일/푸시 · 요청 로그 · 예약 작업 같은 코드가 이 앱 안에 있었다.
- 2026-07 무렵 같은 홈서버에 다른 개인 앱(work-nexus)이 생겼다 — 같은 DB 서버를 같이 쓰게 됐다는 기록이 있다(`bae519e`). 지금은 pace-log 서버 · safe-box 서버도 `@leejinyoung-kr/core-*` 를 쓴다.
- 이 레포를 public 으로 공개하면서(2026-10-15) 공통 코드 레포도 공개할지 정해야 했다.

당시 기록에 남은 것:

- **패키지로 뺀 이유는 이 레포 기록에 없다.** `c2fdb9b` 은 방법만 적었다 — "로직은 원본과 동일, import 경로만 변경. 실제 서버 구동 + HTTP 요청(404/400/페이지네이션)으로 동작 동일함을 확인."
- 서버가 아니라 라이브러리로 둔 이유 (워크스페이스 정리 계획 §6, 비공개 메모, AI 작성): "아웃박스는 앱 DB 트랜잭션과 함께 커밋돼야 하고, 암복호화를 원격으로 빼면 평문·키가 네트워크로 나간다. 코어 서버가 죽으면 모든 앱이 같이 멈춘다"
- 교체해도 암호문이 그대로 풀린다는 근거: "공개 인터페이스·암호문 형식은 같다 (young-core spec/vectors/crypto.json 통과)" — `c6cb96f`
- 비공개 유지: "~~공개한다~~ → 비공개 유지 (2026-10-15 변경 — 개인용 라이브러리). 대신 설계와 핵심 코드 발췌를 core-libraries.md 로 이 레포에 둔다. npmjs 배포는 하지 않는다" — [공개 준비 계획](../archive/2026-10-13-public-release-plan.md)
- "같은 기능을 프로젝트마다 다시 만들지 않으려고 패키지로 뺐다." — [README](../../README.md) 「기술 선택 이유」. 2026-10-15 에 쓴 **사후 설명**이다.

## 지금 검토 — 대안 비교 *(AI 초안 · 본인이 읽고 고친다)*

| 대안 | 장점 | 단점 | 이 프로젝트에 대입하면 |
| --- | --- | --- | --- |
| 앱 안에 그대로 (필요하면 복사) | 한 레포에서 다 보인다. 공개 레포를 누구나 빌드한다 | 같은 수정을 앱마다 한다. 보안 수정이 퍼지지 않는다 | 지금은 쓰는 앱이 셋(이 앱 · pace-log 서버 · safe-box 서버)이라 복사 비용이 생긴다 |
| 모노레포 하나 (앱들 + 코어) | 버전 · publish 없이 바로 공유, 한 커밋에 같이 바뀐다 | 앱마다 공개 범위 · 배포가 다르면 못 합친다 | 이 앱은 public, 다른 앱은 private 이라 맞지 않는다 |
| **지금**: 별도 레포 + 비공개 GitHub Packages + Changesets | 한 번 고쳐 여러 앱에 버전으로 나간다. `spec/` + 테스트 벡터로 언어 사이 호환을 고정 | 버전 올리기 · publish · PAT 관리. 공개 레포를 남이 빌드할 수 없다. 면접관이 핵심 코드를 직접 못 본다 | README 가 "읽기 권한이 있는 계정에서만 설치된다" 고 밝히고 데모로 대신한다 |
| 공개 패키지 (npmjs) | 공개 레포가 그대로 빌드된다 | 개인용 API 를 공개로 유지보수한다 | 계획서가 "npmjs 배포는 하지 않는다" 로 정했다 |

- **지금 보니 맞는 점 (초안)**
  - 라이브러리라서 아웃박스가 앱 DB 트랜잭션에 같이 들어간다 (서버였으면 불가능).
  - 저장소를 앱이 구현하게 해서 코어가 테이블을 모른다.
- **아쉬운 점 · 위험 (초안)**
  - 처음 뺄 때 이 레포에서 확인되는 사용처는 이 앱 하나였다. 지금 워크스페이스 규칙은 "두 번째 프로젝트가 생기거나, 첫 프로젝트가 오래 갈 게 확실할 때" 뽑는다 이다 — 7월이 어느 쪽이었는지는 기록에 없다.
  - 공통 코드의 버그는 모든 앱에 퍼진다. `core-auth` 0.1.0 의 `JwtStrategy` 가 토큰 종류를 보지 않아 refresh 토큰이 access 로 통과했다 (`f9dcdfd`).
  - 이름 · 레포를 두 번 바꿨다 (`@leejinyoun` → `@leejinyoung-kr`, nexus-core → young-core). 그때마다 lockfile · `.npmrc` · Docker 빌드를 같이 고쳤다.
  - 공개 레포인데 핵심 구현이 밖에 있어, "이 코드 직접 짰나" 질문에 보여 줄 것이 요약 문서뿐이다.
