# ADR (설계 결정 기록)

**이 폴더의 ADR 은 소급 기록이다.** 이 앱은 AI 가 제안한 설계를 그대로 채택해 만들었고, 당시에는 대안을 검토하거나 리뷰 · 검증을 하지 않았다. 2026-10 부터 결정마다 대안을 사후에 비교하며 이 문서를 채우고 있다.

- **당시 결정** 칸에는 커밋 메시지 · 코드 주석 · docs 에 **실제로 남은 이유만** 인용하고 출처(커밋 해시 · 파일)를 붙인다. 그 이유도 AI 가 쓴 것이다. 기록에 없으면 "기록에 없다" 고 쓴다.
- **지금 검토** 칸은 AI 초안이다. 본인이 읽고 고친다.
- **다시 정한다면** 칸은 본인만 쓴다. 비어 있으면 아직 검토하지 않은 것이다.

## 템플릿

새 소급 ADR 은 아래 틀을 그대로 쓴다. 파일 이름은 `NNNN-<영문-slug>.md`.

```markdown
# NNNN. <결정 한 줄>

- **상태**: 채택 (소급 기록)
- **결정일**: YYYY-MM-DD (근거 커밋 `abc1234`)
- **기록일**: YYYY-MM-DD
- **결정 방식**: AI 제안을 그대로 채택 — 당시 대안 검토는 없었다

## 맥락
무엇을 정해야 했나. 사실만.

## 당시 결정
무엇을 골랐나. 당시 기록에 남은 이유가 있으면 인용 + 출처 「당시 기록(AI 작성)」. 없으면 "기록에 남은 이유 없음".

## 지금 코드에 남은 것
결정이 구현된 파일 경로 · 설정 (확인한 것만).

## 지금 검토 — 대안 비교 *(AI 초안 · 본인이 읽고 고친다)*
| 대안 | 장점 | 단점 | 이 프로젝트에 대입하면 |
2~3개 대안. 일반론이 아니라 이 프로젝트 규모(1인 · 홈서버 · 사용자 몇 명)에 대입.
- 지금 보니 맞는 점 (초안)
- 아쉬운 점 · 위험 (초안)

## 다시 정한다면 — 본인 작성
> *비어 있음.* 위 비교를 읽고 같은 선택인지, 바꾼다면 무엇을 왜 바꾸는지 한 줄.
> 생각할 질문: (이 결정 고유의 질문 2~3개)

## 면접 예상 질문
- 3~5개
```

| 지금 검토 | AI 초안 → 본인이 고친다 | "확인 필요" 표시는 코드를 열어 확인한 뒤 지우거나 고친다 |
