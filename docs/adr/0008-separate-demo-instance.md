## 지금 검토 — 대안 비교 *(AI 초안 · 본인이 읽고 고친다)*

| 대안 | 장점 | 단점 | 이 프로젝트에 대입하면 |
| --- | --- | --- | --- |
| 운영 인스턴스에 데모 계정 | 인스턴스 · 배포가 하나 | 운영 DB 에 남이 들어온다. 권한 버그 하나면 실제 데이터가 보인다. 허용 목록에 예외가 생긴다 | 계정 비밀번호를 보관하는 앱이라 위험이 가장 크다 |
| 화면 캡처 · 영상만 | 운영 부담이 없다 | 눌러 볼 수 없다 | 목표("사이트에 바로 들어가 둘러보고")와 맞지 않는다. README 캡처 4장은 같이 둔다 |
| **지금**: 같은 장비에 별도 인스턴스 + 매일 초기화 | 데이터 · 키 · 버킷 · 주소가 운영과 갈린다. 코드는 하나 | 같은 장비 · 같은 MariaDB 라 자원과 장애는 나눠 쓴다. 초기화 설정이 레포 밖에 있다 | 데모 방문자가 몇 명뿐이라 자원 문제는 작다 |

- **지금 보니 맞는 점 (초안)**
  - 데모 로그인 라우트가 운영에는 아예 없다 (부팅 로그 `Mapped` 에 안 나온다). 운영에서 데모 로그인으로 우회할 길이 없다.
  - 운영과 다른 키라, 데모 쪽이 털려도 운영 암호문 · 토큰에 닿지 않는다.
- **아쉬운 점 · 위험 (초안)**
  - 방문자 모두가 계정 하나를 같이 쓴다. 한 방문자가 넣은 내용이 다음 날 04시까지 다른 방문자에게 보인다.
  - 데모 주소는 Funnel 로 공개돼 누구나 파일을 올릴 수 있다. 막는 것은 50MB 한도 · 버킷 수명 주기 · 데모 로그인 분당 10회다.
  - 초기화 crontab 이 git 밖이라, 서버를 다시 세울 때 빠뜨리기 쉽다.
  - 실행 이미지에 `src` 가 없어 초기화 시드가 처음에 깨졌다 (`045cb5d`) — 로컬은 `src` 가 있어 통과했다. 로컬과 운영 이미지가 다르다는 것을 보여 준 사례다.
